## Initialization safety

The seventh MCP tool, `initialize_project`, requires a caller declaration of an
explicit user request and an explicit destination. This declaration does not
authenticate user consent; the invoking agent must honor the user's intent and
host permissions. Missing build files alone never authorize generation.

The runtime rejects existing build contexts in the active workspace or
destination ancestry, traversal and symlink paths, and any preexisting target.
It downloads only from official Spring Initializr, refuses redirects, bounds
downloads and archive expansion, rejects unsafe ZIP entries, stages privately,
and publishes with an exclusive atomic rename. It never executes generated
code. Regression fixtures cover malformed archives, interrupted extraction,
destination races, parent replacement, existing projects and network failures.

The destination must be absent with an existing parent. Empty existing targets
are intentionally refused; no cleanup/overwrite fallback is offered. Atomic
publication is implemented for Linux and macOS, not native Windows. The shared
runtime already depends on POSIX facilities. Use Linux/macOS/WSL; macOS behavior
must also pass the CI matrix rather than being inferred from a Linux result.

A live official Initializr request generated a Maven/web project in a temporary
directory, reported the actual metadata-selected versions, and did not run a
build. A subsequent request from that project was refused before writing.

## Codex compatibility

Codex has its own compatibility manifest and MCP configuration. The adapter
preserves application cwd and explicitly resolves the installation path; it
does not reuse Claude interpolation or treat the plugin checkout as the app.
See [Codex setup](codex.md) for launcher requirements and host verification.

Claude edit guards, Stop hook, specialist-agent registrations and Java LSP are
not registered on Codex. Shared skills explain direct review and explicit full
verification instead of claiming host parity. No global account/trust settings
or plugin installations are changed by this implementation.

## Validation and limits

The director executed deterministic regressions, syntax checks, dependency
audit, strict Claude manifest/skill/agent validation, a real Initializr smoke
generation and Java examples. Java execution includes smoke assertions,
consumer/provider Pact compatibility (including an expected breaking-provider
rejection), and a local Gatling run with actual requests and assertions.
The Codex specialist exercised protocol/config discovery with isolated state;
no model turn or paid behavioral evaluation is required for packaging tests.

Final local evidence: all 11 suites passed through `tests/run-all.sh`.
After the final report-scope and structured-error corrections, the two affected
suites were rerun: 22 Python runtime regressions and 35 MCP tests passed.
The initializer suite passes 20 tests; the Codex adapter passes seven tests.
The isolated Codex CLI 0.166.0 probe confirms 16 skills, no hooks, seven tools
and the actual application cwd without a model turn. Strict Claude validators,
skill validators, syntax checks and `git diff --check` passed. Dependency audit
reports zero current vulnerabilities. Java smoke/Pact/Gatling checks passed
again after the audience-example correction.

Remaining validation gaps are distinct from demonstrated defects:

- No paid behavioral evaluation or claim that all generated outputs follow the
  skills. Existing frozen-response/criterion tooling remains available.
- No production database, container deployment, broker publication or load
  acceptance was certified; local fixture results are not production evidence.
- Real multi-module Maven filtered-test behavior with `-pl/-am`, dynamic Gradle
  settings and external build inputs need application-specific validation.
- Aggregate source scan budgets and adversarial concurrent mutation by another
  process with the same OS user are not comprehensively bounded. Repository
  builds and wrappers remain trusted executable code.
- Hook scalar-secret/DDL checks are heuristic and fail open with diagnostics;
  they are not a substitute for independent secret/security scanning.
- Claude's local validator reports an optional missing directory-listing icon;
  local manifest validation passes. Public directory submission and publication
  were outside this task.
